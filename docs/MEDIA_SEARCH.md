# Public image and GIF search

`image.search` and `gif.search` query the official [Wikimedia Commons API](https://commons.wikimedia.org/wiki/Commons:API/MediaWiki), returning up to five supported raster files with artist, credit, license label and source file page. GIF search covers Commons GIF files. Giphy, Tenor, premium catalogs and arbitrary web image scraping are not part of this provider.

No additional API key is required. Queries use the File namespace and [file MIME/size filters](https://www.mediawiki.org/wiki/Help:CirrusSearch#File_properties_search), then independently check each returned MIME type, dimensions and size. Eligible files are PNG, JPEG, WebP or GIF, at most 2 MiB and 40 million image pixels. Search JSON is limited to 256 KiB. Identical public queries share a five-minute cache capped at one hundred entries, with at most four active distinct queries.

Each search creates a separate immutable ten-minute selection bound to the caller, guild and text channel. The returned `send` object contains the exact search ID, index and displayed title. Pass it to `media.search-send`; the action requires the usual explicit confirmation. It downloads only the selected returned upload, checks HTTP content type and actual image metadata/signature, then refreshes membership and verifies the caller and bot still have View Channel, Send Messages (or Send Messages in Threads) and Attach Files. It includes source/attribution text and disables mentions. Search tokens are bounded to ten per user/server, one hundred per server and five hundred globally; expired tokens are pruned on searches.

Both API calls and downloads reuse the public integration transport, which validates DNS addresses and pins the HTTPS connection to a validated public address. Redirects are rejected. API requests use only `commons.wikimedia.org`; downloads use only `upload.wikimedia.org/wikipedia/commons/`. Known tracking parameters returned by Commons are stripped. No user-supplied URL can be substituted into a send action. Each result is claimed before the Discord send; an ambiguous HTTP failure leaves it unavailable for automatic retries, preventing duplicate posts. A user can review the channel and start a new search if another explicit attempt is needed.

License labels and credits are returned from Commons metadata. The full file page remains the source for complete license terms and attribution details. The bot includes that link when posting an image; it does not independently certify the correctness or completeness of a third-party uploader's licensing claims.

Tests use real PNG bytes and a controlled DNS-pinned transport to verify cache and quota bounds, namespace/MIME filters, user/channel binding, registry confirmation, current thread permissions, delayed authorization loss, format/type/size rejection, expiry, private DNS rejection and ambiguous-send behavior. Public read-only probes on this host returned five image and five GIF results from the real Commons API. No Discord messages were sent during those probes.

# Local voice transcription

Vibe can detect spoken requests locally with Transformers.js and the quantized `Xenova/whisper-tiny.en` model used by the previous voice bot. This avoids sending every ambient utterance to OpenAI and does not consume remote transcription request quota. Local transcription does not itself authorize a spoken response: individual consent and the wake-name/follow-up rules still apply.

The CPU model runs in a separate ESM worker and initializes only when prepared or first used. Native inference uses two intra-operation threads and one inter-operation thread. One utterance runs at a time with at most four waiting; queued audio older than fifteen seconds is discarded. An inference/model-loading deadline is sixty seconds. Missing or broken local inference produces setup guidance and never silently uploads ambient audio to a remote fallback.

Run `pnpm voice:prepare` to download/warm the selected public model before joining voice. The host-selected model ID and cache directory are configuration, not Discord action inputs. The default English model is small and optimized for English; choosing a compatible multilingual Whisper model requires the appropriate host resources and model preparation. Input audio must be valid mono/stereo PCM16 WAV at 8–48 kHz, no longer than fifteen seconds and at most 8 MiB. It is downmixed/filtered to mono Float32 at 16 kHz.

Only the local worker receives those samples. Queued samples are zeroed on cancellation/discard; transferred worker samples are zeroed after inference, including failures and cancelled outputs. Cancelling a running local inference immediately rejects its caller and drops its result while the bounded native job finishes; a hung job terminates its worker at the deadline. Shutdown waits for worker termination.

Model weights live under `.cache/models` and are excluded from Git, image build context and the portable source ZIP. A new machine must prepare/download its own model cache, or the operator can deliberately copy the matching public weights there. Preparing a model downloads model assets; it does not upload conversation audio or require another API key. Cache-only operation can disable remote model downloads. A failed worker/model must be repaired and Vibe restarted.

The portable source default remains `LOCAL_WHISPER_MODEL=Xenova/whisper-tiny.en`. A host can select `Xenova/whisper-base.en` for a larger English model, run `pnpm voice:prepare`, then restart. Model size alone does not establish recognition accuracy for a particular microphone or speaker; verify the actual wake name and complete requests on that host.

An isolated Windows benchmark used the same 1.9-second synthetic greeting, “Hi, I am Vibe,” for both q8 models. Both returned that greeting correctly in every run. Tiny prepared from cache in about 534 ms and transcribed in 246–331 ms; Base prepared in 706 ms and transcribed in 357–432 ms. Their public model caches were about 41 MiB and 75.4 MiB. The measured process peaks were about 973 MiB for Tiny and 1,772 MiB for Base; Base retained about 1,350 MiB after the short idle period. Those are local measurements, not guarantees for other hardware or improved human wake-name recognition. Base's first download and initialization took about 2.26 seconds on this connection.

Docker Compose passes the same `LOCAL_WHISPER_MODEL` value into the image build and runtime. The build downloads and prepares that selected model, then copies its cache into the unprivileged runtime image. After changing the model, rebuild with `docker compose up --build -d` so the chosen weights are present; changing only the runtime environment cannot add a missing cache. A direct Docker build can pass `--build-arg LOCAL_WHISPER_MODEL=Xenova/whisper-base.en`.

`BOT_MEMORY_LIMIT=3072m` is the configurable Compose default. Base needs room beyond its roughly 1,772 MiB measured process peak for the bot and other enabled features; the old 1,536 MiB limit is insufficient for that measured workload. Three GiB is a starting allocation rather than a capacity guarantee. Monitor the complete deployed process and adjust the host/container budget for concurrent file work and voice sessions. Tiny remains available for hosts with fewer resources. Docker configuration was updated from source review; no Docker build or container-memory acceptance was performed on this Windows host.

Local checks exercise format conversion, admission bounds, stale queues, cancellation, deadlines and input zeroization. A real cached-worker acceptance test loaded the q8 model and transcribed a generic synthetic Vibe greeting without remote API calls.

Pure non-speech annotations such as repeated `[BLANK_AUDIO]`, `[shh]` and `(blows kiss)` are discarded before transcript logging, meeting excerpts and request addressing. Recognized annotations mixed with actual speech, unknown bracketed text, quoted labels and short commands such as “Vibe,” “confirm” and “stop” are preserved. This filter does not guess whether arbitrary recognized words were ambient speech.

The optional acoustic VAD uses a −42 dB energy threshold over 20 ms frames, requiring activity in at least 5% of the frames. This detects acoustic energy rather than semantic speech. A local synthetic test confirms it rejects completely zero PCM, but it also rejects a nonzero quiet waveform with peak 100/32768 and about −53 dB RMS. Raising the default gate would therefore risk losing quiet commands without microphone evidence; exact digital silence can be discarded independently of that opt-in threshold.

# Automatic moderation

Automatic moderation handles new messages and message edits in the configured servers. It does not scan historical channel contents. Spam checks run before API classification; content awaiting classification receives no community XP or FAQ response. A handled message stops downstream conversation and workflow processing.

## Configuration

`AUTO_MODERATION_ENABLED=true` enables the automatic explicit-content and honeypot event handlers. Keep the intended server IDs in `DISCORD_GUILD_IDS`. New per-server policies are initialized from the environment only when no policy is already stored; changing an environment default does not replace an existing server policy. Restart after changing environment settings.

| Setting                     | Purpose                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `OPENAI_API_KEY`            | Existing key used for explicit text and still-image classification.                                                      |
| `OPENAI_MODERATION_MODEL`   | Classification model; default `omni-moderation-latest`.                                                                  |
| `MODERATION_TIMEOUT_MS`     | Requested classifier deadline; the classifier bounds the complete operation to at most 12 seconds.                       |
| `MODERATION_LOG_CHANNEL_ID` | Dedicated private destination for automatic moderation case outcomes. Blank disables Discord case notifications.         |
| `HONEYPOT_CHANNEL_ID`       | Posting in this channel or its threads triggers deletion and an automatic ban attempt. Blank disables the honeypot rule. |

The per-server policy separately controls `enabled`, `textEnabled`, `imagesEnabled`, `honeypotChannelId` and `logChannelId`. The moderation feature switch and allowed-server checks still apply. Message Content intent must be enabled in configuration and the Discord Developer Portal for ordinary message bodies and attachments to be available to the bot.

Custom spam protection uses the existing `community.configure` action and its independent `antiSpamEnabled` setting. `antiSpamExemptStaff` defaults to `true` for compatibility; set it to `false` to include members with Manage Messages and administrators. `repeatLimit` accepts 2–10 matching posts and defaults to 4; `mentionLimit`, `messageLimit` and `blockedKeywords` adjust the other local rules. The current server profile uses `repeatLimit: 3`. Disabling the community or moderation feature suppresses custom spam enforcement.

## Supported detection and effects

Spam detection handles the configured number of matching normalized messages within eight seconds, repeated attachment URLs, more than the configured message count within that window, mention limits and configured keyword matches. Reaching the repeat threshold removes all matching observed posts in that burst, preserving distinct neighboring posts. The explicit history-cleanup action uses the same threshold for retained spam. Attachment-only messages are included; CDN signature query changes do not disguise the same attachment URL. Reuploaded files with different attachment URLs rely on flood limits unless another rule matches. Ordinary accepted messages retain the existing XP cooldown and exact-match FAQ behavior.

Fast local rules remove configured-policy slurs, sexual-abuse terms, adult-domain links and adult advertisements from the first matching message without waiting for a provider. They normalize compatibility glyphs, invisible formatting and common letter substitutions, while word boundaries protect unrelated words. These strict rules may match quoted or educational uses; ordinary profanity alone is not a deletion rule. Message bodies and link-preview titles, descriptions, authors, footers, fields and URLs are inspected. Clear nested redirect parameters are decoded locally; opaque redirect links can be identified from their preview metadata. Arbitrary redirect destinations are never fetched.

Semantic classification sends bounded text and decoded still-image pixels to OpenAI. Automatic removal includes sexual, hate, threatening hate and threatening harassment categories. Hate/threatening decisions and sexual/minors are text-only; this does not promise recognition of hateful symbols in image pixels. Sexual image decisions use pixel classification rather than filenames. Text and image policies can be enabled independently. Staff have no automatic exemption; Vibe skips its own messages and Discord system messages. Other bots and webhooks are scanned. Honeypot handling can remove a webhook post but cannot ban a webhook identity.

The honeypot rule attempts to delete the triggering message and ban its author without another confirmation. Discord still controls the bot's ability to ban: the server owner, the bot itself and members at or above its highest role cannot be banned through this rule. Missing permissions or hierarchy restrictions produce a blocked outcome. A transport failure with an unknown ban result requires manual reconciliation and is not retried automatically.

Bot/channel permissions, current policy, message identity and content revision are checked again before effects. Content edits invalidate an older classification snapshot. Deleted spam receives no XP or FAQ reply; a failed spam deletion still suppresses downstream bot processing.

## Private cases and limits

Automatic cases retain identifiers, category labels, attempted effects and outcomes in the local database. They do not retain image bytes or message bodies. Case notifications go only to a verified private text channel with explicit @everyone visibility denied and no ordinary role granted access. Selected member overwrites and the bot's own managed role are supported; Discord administrators retain their platform-level access. An invalid or unavailable private destination has no public fallback. Cases older than 90 days are pruned during periodic admissions.

Ordinary scans have three active slots and up to 64 waiting jobs. Honeypot candidates use a separate reserved lane with two active slots and 64 waiting jobs, so classifier load cannot exhaust honeypot capacity. Cached channel identity selects the lane; fresh channel, policy and authority checks still determine enforcement. Both lanes have a 30-second service deadline. Each classifier call has a maximum 12-second total deadline, up to ten still-image candidates, bounded downloads and a 16-megapixel decoding limit. Images are resized to at most 1024 pixels per side and submitted sequentially with at most one image per API request. Text accompanies the first scannable image, or uses a text-only request when no image is scannable. Subsequent image-only results cannot create text-only category decisions. A positive verdict returns immediately, preserving the decision and reporting the number of images actually classified. All requests share the same 12-second deadline. Default input-file size is 8 MiB, subject to the configured attachment limit and a 32 MiB aggregate download budget. Message text is limited to 4,000 characters; message plus embed metadata is bounded at 12,000 characters.

Animated or multipage images, video, unsupported formats, unavailable previews and data beyond the scan bounds are not fully classified. Unscannable content and provider errors are reported for review and never establish that a message is clean. Queue saturation, API access, network availability and Discord permissions can prevent automatic removal. These bounded automated decisions do not guarantee detection of every explicit image or spam pattern.

Offline tests exercise detection, permission changes, cancellation, image handling and duplicate-effect protection. The installed moderation API was also tested with a harmless generated image and a non-graphic sexual solicitation; it preserved the safe input and classified the solicitation for removal. No real member was banned for testing. Native spam/mention blocking and Discord's all-member explicit-media filter are enabled for this installation. The honeypot is exempt from those two spam rules so a posted message reaches Vibe's ban handler.

Use `/action name:moderation.automatic.status` for the active policy and recent private outcomes. `/action name:moderation.automatic.configure` changes the per-server policy through one exact approval; enabled automatic removals and honeypot bans do not prompt anyone for confirmation. The installed local keyword policy also blocks known adult-site domains and obvious porn advertisements to complement model classifications. Classifiers can miss harmful content or flag benign content; unknown service results are logged rather than described as successful removals.

## Requested history cleanup

`moderation.history.clean` inspects a readable channel's recent 100 messages by default, or up to 500 with `limit`, and returns a `before` continuation for older history. An authorized direct request in smart mode executes without another approval. Natural requests such as “review chat and remove explicit messages” expose this typed action to the AI planner with the current channel as its default. Message cleanup is explicitly blocked from substituting channel deletion.

Cleanup applies local rules, semantic decisions and configured historical spam windows, individually deletes matched posts including those older than fourteen days, and preserves neighboring accepted posts, Vibe/system messages and the private moderation log. It never bans historical authors or deletes their channel. Current requester/bot permissions, settings and message revisions are checked before each effect. A two-minute operation deadline, two concurrent cleanups and provider-failure limits bound the work; the result reports actual counts, incomplete scans and a continuation rather than inventing completion.

# AI policies, sources and reviewed plans

The configured OpenAI key serves chat, images, speech, transcription and embeddings. Optional integrations use their own explicitly supplied configuration; see the deployment/configuration guide. No action creates an account, purchases a service or assumes that a model is available to the account.

`ai.access.configure` lets a manager set server, administrator and individual policies: enabled state, tool/web permissions, a daily request ceiling and a configured model route. Effective permissions intersect; the strictest daily ceiling remains in force even when a premium plan supplies a larger allowance. `ai.access.view` shows the caller's effective settings and routes, and `ai.access.remove` removes an override. Policy changes invalidate pending policy-bound AI work.

`AI_MODEL_ROUTES_JSON` optionally maps route names to account-accessible model IDs. The automatic router sends coding/debugging keywords to `coding`, reasoning/calculation/planning keywords to `reasoning`, and other prompts to `general`. Unconfigured routes fall back to the normal configured chat model; a more specific access policy can choose a fixed route. This is a deterministic router, so its choices are inspectable and do not require another paid classification call.

`math.calculate` and the AI `calculate` tool use exact rational arithmetic for bounded decimal expressions, parentheses, `+ - * / % ^` and unary signs. They never evaluate code. Results include the reduced fraction, decimal rendering and rounding flag. The parser bounds expression length, depth, token count, exponent and integer size.

`ai.document.analyze` accepts an explicitly supplied Discord attachment: images/PDFs use the configured vision-capable model; supported Office/text documents use the local extractor before analysis. `ai.article.summarize` fetches one approved public HTTPS article with public-address validation and a 1 MiB response cap. Scripts/styles/markup are removed. `ai.log.analyze` accepts only fixed host log IDs from `AI_LOG_FILES_JSON`, requires both operator and Manage Server authority, caps the regular file at 1 MiB and redacts configured secrets before upload. Empty log configuration disables host-file access.

Text analysis uses up to twelve 2,500-character excerpts and one synthesis request. Results report actual analyzed/source characters, request count and truncation. Source instructions are treated as untrusted data; these workflows use no personal context, history, administrative tools or web search. History answers additionally paginate current readable channel history and list selected message IDs. Model/image/PDF limits and local extraction limits still apply; there is no universal binary-file parser. See [knowledge and history](KNOWLEDGE.md) and [supported files](FILES.md).

`ai.plan.create` saves a private immutable plan of 1–10 strict registered actions (at most 32,000 JSON characters per step). Up to twenty plans can be retained per person/server. `ai.plan.view` returns the exact next action, input, revision and step index. `ai.plan.step` executes only that exact reviewed step after its ordinary one-use human confirmation, current action permissions/policies and any configured staged role approvals. Plans cannot invoke plan or approval-chain controls recursively. They work across restarts without depending on provider conversation storage.

Successful steps advance the revision. Failed or interrupted operations enter `review-required`; `ai.plan.reconcile` requires explicit inspection of external state before marking a step completed or allowing a separately confirmed retry. It refuses reconciliation while an operation is still active in the current process. `ai.plan.cancel` blocks future steps; an already-started external operation can finish and is recorded accordingly. `ai.plan.remove` deletes an inactive retained plan. Personal AI erasure deletes plans/approval chains and prevents waiting steps from resuming. These workflows do not promise atomic rollback of unrelated Discord/provider operations.

`analytics.api` exposes bounded per-provider/endpoint counts, errors and mean/maximum latency. It stores neither request payloads nor credentials. AI endpoint metrics are recorded automatically; other adapters can use the same aggregate recorder. [Ticket AI](TICKET_AI.md) documents separately approved support classification/routing.

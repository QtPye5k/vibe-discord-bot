# Conversational actions

An addressed request can use the same typed Discord actions as exact commands. The assistant receives the current member/server/channel, UTC/local time, permitted channel names and IDs, current voice channel when visible, real pending confirmation IDs, and the relevant common action schemas. Names and prior turns are data; they never grant new authority. The registry still rechecks current permissions, action policies, premium access and request provenance before a mutation.

Ordinary authorized changes follow the configured confirmation policy. The assistant requests the real action before describing any pending operation. Required approvals are posted only to the dedicated private `bot-confirmations` channel, where a human whose highest role is strictly above Vibe can approve or reject. Original requesters retain their own permission requirements; approval never lends them staff privileges. A completed operation is reported as completed, including when a later language-model summary fails. The model cannot manufacture a pending action by saying “please confirm.” See [CONFIRMATIONS.md](CONFIRMATIONS.md).

For incomplete requests the assistant uses reasonable defaults instead of a long form: the configured local time zone, the next upcoming requested clock time, two hours for casual gaming, the member's current voice channel or the only available one, normal server event visibility and no unsolicited mentions. It preserves the original topic across clarification. It asks one short question when a required target cannot be inferred. Platform validation rules and permissions still apply; the assistant cannot invent unsupported private-event visibility or bypass a required valid server name.

Scheduling uses the deterministic `resolve_datetime` tool. Today and tomorrow are calendar dates in the configured local zone, including when UTC has already crossed midnight. The tool supplies exact UTC start/end times, validates calendar dates and rejects nonexistent or repeated daylight-saving wall times for clarification. AI-created or edited event timestamps must match a resolver result from that same turn; the model cannot invent its own UTC conversion.

Public mention context is separate from private `/ask` history, saved preferences and pinned memories. Shared/voice callers can retain a short leased history using `historyTtlSeconds`; each record is bound to server, channel, scope and member. Expired leases are ignored/deleted on read and removed by routine maintenance. Private history retains its separately configured policy. Erasure invalidates late provider results and prevents history resurrection.

Mentions support the entire available typed action catalog, including settings, reminders, reports, tickets and AI helpers. Exact alternatives such as `@Vibe status`, `@Vibe schema role.edit` and `@Vibe action ACTION_ID {JSON}` also work without a planning request. Slash commands remain available. A public mention that invokes a private action first proves DM delivery, then delivers the complete result privately; blocked DMs prevent that action from starting. Private results never enter public mention history. AI helpers share their parent request's concurrency slot, consume their own API quota and inherit cancellation; nested analysis cannot start another action-planning loop.

Voice replies are audible to other channel members, so they retain public-response restrictions even when transcripts go into a private channel. Public server-resource actions still require the member's actual authority. Channel names included as context are filtered by visibility, including normal public visibility for public responses. For media use `@Vibe send a bunny GIF from Klipy in #general`, `@Vibe send this Pinterest Pin in #general: LINK`, or `@Vibe generate a watercolor rabbit and post it in #art`. See [MEDIA_SEARCH.md](MEDIA_SEARCH.md) for provider access requirements.

An addressed request can carry an in-memory cancellation lease. For voice this lease belongs to the current session, speaker, consent and channel. It is rechecked after awaited authorization, provider and tool work and immediately before action execution or history persistence. Stop, departure, consent revocation or session replacement therefore prevent delayed plans from starting new mutations or recreating cleared history. Expired or cancelled requests fail explicitly instead of becoming new confirmation previews. This cannot undo a remote operation that was already sent before cancellation.

Realtime speech is admitted through the same AI role/access policies, daily request allowances and concurrency limits as text chat. A provider change does not create a separate quota allowance.

## Latency

The original GPT-5 family uses minimal reasoning and low output verbosity for ordinary tool/chat work. Hosted web search uses low effort because the [web search guide](https://developers.openai.com/api/docs/guides/tools-web-search) excludes minimal reasoning. Other configured models keep their supported defaults. Voice planner output is capped at 700 tokens and normally one to three sentences. Common action schemas are supplied on the first request, and `find_actions` returns ranked results with their schemas, reducing extra discovery round trips. The [official latency guide](https://developers.openai.com/api/docs/guides/latency-optimization) explains why shorter output and fewer sequential calls improve response time.

The archived previous bot used persistent `gpt-realtime-2.1` sessions with Marin and streamed audio, rather than waiting for separate transcription, text generation and speech generation calls. `VOICE_RESPONSE_BACKEND=realtime` uses that persistent per-speaker renderer for ordinary conversational speech while keeping typed action planning in the permission-checked registry. Realtime speech must never claim that an external operation completed without a real action receipt. `VOICE_RESPONSE_BACKEND=pipeline` retains separate text and speech generation.

Only clearly conversational voice input uses the tool-free renderer. Unfamiliar action requests, channel dictation, and role/rule color wording reach the real planner. Empty dictation asks one content question; an admitted content continuation is serialized as JSON data and restricted at tool dispatch to resolving a channel and sending the exact body. It cannot add mention grants, attachments, TTS, or another mutation. Cancellation propagates into local transcription and provider calls. A verified completed mutation is recorded before later lease checks; an interrupted result acknowledges that completion rather than telling the user to repeat the action.

`VOICE_TRANSCRIPTION_BACKEND=local` uses a prepared CPU Whisper worker to recognize consented speech and check name-triggered requests locally. Run `pnpm voice:prepare` to cache `LOCAL_WHISPER_MODEL=Xenova/whisper-tiny.en` in `.cache/models`; no OpenAI request or audio upload occurs during preparation. Only accepted addressed text is forwarded for an AI reply. Choosing `VOICE_TRANSCRIPTION_BACKEND=openai` explicitly uses remote transcription for captured consented utterances before checking the name. See [LOCAL_TRANSCRIPTION.md](LOCAL_TRANSCRIPTION.md).
